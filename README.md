# Лабораторная работа. Многопоточность и асинхронность в Go

**Подготовка:** функции, циклы, структуры и обработка ошибок в Go.

## Цель

Реализовать пул обработчиков на горутинах, передать задания и результаты через каналы, ограничить время работы через контекст и проверить программу на гонки данных.

## Условие

Программа получает восемь заданий с числами от 1 до 8. Для каждого задания она имитирует ожидание внешнего ресурса в течение 200 мс, затем вычисляет квадрат числа. Результат хранит исходное число и его квадрат. Порядок получения результатов может отличаться от порядка выдачи заданий.

Создайте отдельный модуль командами `go mod init lab/concurrency` и `go mod tidy` после написания кода. Используйте стандартную библиотеку Go. Для запуска программы используйте `go run .`.

## 1. Последовательная обработка

Напишите функцию обработки одного задания. Для имитации ожидания используйте `time.NewTimer` и `select` с двумя ветками: срабатывание таймера и получение сигнала из `ctx.Done()`. При отмене верните `ctx.Err()`. Остановите таймер при выходе из функции.

Обработайте восемь заданий в цикле. Измерьте общее время через `time.Since`. Проверьте, что получили восемь результатов и сумма квадратов равна 204.

## 2. Пул горутин

Реализуйте функцию с интерфейсом:

```go
type Result struct {
    Input  int
    Square int
}

func runPool(ctx context.Context, inputs []int, workers int) ([]Result, error)
```

1. Верните ошибку, если число обработчиков меньше единицы.
2. Создайте каналы заданий и результатов. Отдельная горутина отправляет задания и закрывает канал заданий после завершения отправки.
3. Запустите заданное количество обработчиков. Каждый берёт очередное задание, вычисляет результат и отправляет его в канал результатов.
4. Используйте `sync.WaitGroup` для ожидания обработчиков. Вызывайте `Add` до запуска горутин, а `Done` — при выходе. Отдельная горутина ждёт всех обработчиков и закрывает канал результатов.
5. Соберите результаты в вызывающей горутине через `for result := range results`. Для печати по возрастанию отсортируйте их по полю `Input`.

## 3. Отмена по таймауту

Создайте контекст через `context.WithTimeout` и вызовите `defer cancel()`. При отправке задания, ожидании работы и отправке результата учитывайте `ctx.Done()`. При получении из канала заданий проверяйте, открыт ли он.

При истечении таймаута функция должна вернуть уже полученные результаты и ошибку `context.DeadlineExceeded`. После возврата все горутины, созданные функцией, должны завершиться. Проверьте, что программа не зависает, если контекст отменён ещё до запуска пула.

## 4. Эксперименты

| Режим | Ожидаемый результат |
| --- | --- |
| Последовательно | 8 результатов, сумма 204, около 1,6 с |
| Пул из 1 обработчика | 8 результатов, сумма 204, около 1,6 с |
| Пул из 4 обработчиков | 8 результатов, сумма 204, около 0,4 с |
| Пул из 4 обработчиков, таймаут 300 мс | Частичный результат и ошибка таймаута |

Время в таблице — ориентир для имитации ожидания. Запустите каждый режим трижды, запишите медиану и объясните разницу. Для сравнения укажите ускорение как отношение последовательного времени к времени пула.

Добавьте тесты полного результата, отменённого контекста и неверного числа обработчиков. Для теста полного результата проверяйте все восемь пар, а не только сумму. Запустите:

```text
go test -timeout 15s ./...
go test -race -timeout 30s ./...
```

Для запуска с `-race` нужна среда, которая поддерживает детектор гонок. На Windows при ошибке инструментария проверьте, что доступен совместимый C-компилятор и включён cgo. Успешный прогон проверяет только те пути выполнения, которые прошли тесты.

1. Чем горутина отличается от потока операционной системы?
2. Может ли пул ускорить имитацию ожидания на одном ядре? Почему?
3. Почему канал результатов закрывают после завершения всех отправителей?
4. Что произойдёт, если обработчик ждёт отправки результата, а получатель уже завершился?
