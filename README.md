# Пул обработчиков на горутинах (Go)

Учебный проект по конкурентной обработке восьми заданий.

## Структура

- `main.go` — три запуска последовательного режима, пула с 1 и 4 обработчиками; выводит медиану и разброс времени, затем демонстрирует таймаут 300 мс.
- `concurrency/processor.go` — обработка одного задания, последовательный запуск и пул горутин.
- `concurrency/processor_test.go` — тесты корректности, частичных результатов, неверного числа обработчиков и заранее отменённого контекста.

## Запуск

Из корня проекта:

```bash
go mod tidy
go run .
```

Тесты и проверка гонок:

```bash
go test -timeout 15s ./...
go test -race -timeout 30s ./...
```

## Ожидаемое поведение

Каждое задание занимает около 200 мс. Последовательная обработка восьми заданий и пул из одного обработчика занимают около 1,6 с. Пул из четырёх обработчиков обычно выполняет задания примерно за 0,4 с. При таймауте 300 мс возвращаются уже готовые результаты и `context.DeadlineExceeded`.

В `main.go` каждый из трёх основных режимов выполняется трижды. Для каждого выводятся медиана и разброс от минимального до максимального времени. Фактические значения зависят от планировщика Go и нагрузки системы.

## Краткий вывод

Пул из четырёх обработчиков сокращает время ожидания, потому что четыре задания могут ожидать свои таймеры одновременно. При этом каналы безопасно передают задания и результаты, `WaitGroup` синхронизирует завершение обработчиков, а контекст позволяет остановить отправку и обработку при отмене или таймауте. Отправитель, обработчики и горутина закрытия канала результатов завершаются до возврата `RunPool`.
